# TyMed is a native Android app

Kotlin + Jetpack Compose, no React Native/Expo/JS layer — the project was rewritten from an
Expo/React Native app to pure native Android. Everything lives under `android/` as a normal,
hand-maintained Android Studio project (not generated by any prebuild step).

A few things worth knowing before touching the data layer:

- `android/app/src/main/java/com/tymed/app/data/TymedDatabase.kt`'s `MIGRATION_4_5` exists to
  preserve existing sideloaded users' data (same `applicationId`, same `tymed.db` file/schema) —
  see the doc comment there before changing the Room schema. Never add
  `fallbackToDestructiveMigration()`.
- Bump the `@Database(version = ...)` and add a real migration for *any* entity change, even one
  that looks purely additive — Room validates the on-disk schema exactly.
- `com.tymed.app.data.RecurrenceRule` is the single source of truth for "does this schedule recur
  on this date," used by both the UI and `alarm.AlarmReceiver`. Don't reintroduce a duplicate copy
  of this logic.

See `android/app/build.gradle` for the dependency versions and `store/RELEASE_CHECKLIST.md` for
the release process.
